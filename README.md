# ПанГосподар — інтернет-магазин інструментів

Сайт магазину господарських та садових інструментів (смт Ратне, Волинська обл.).
Побудований на **Next.js 16** (App Router) + **Tailwind CSS 4**, інтерфейс українською.

## Можливості

- **Каталог** з фільтрами (категорія, бренд, ціна, наявність) та сортуванням; фільтри за характеристиками з'являються, коли обрано конкретну категорію
- **Категорії** з мега-меню та підкатегоріями
- **Сторінка товару** з артикулом, залишками, описом і технічними характеристиками
- **Кабінет клієнта** — вхід на 30 днів, обране, історія замовлень, відновлення пароля поштою
- **Кошик** з контролем залишків (не можна замовити більше, ніж є на складі)
- **Адмін-панель** (`/admin`) — керування каталогом, захищена входом за паролем
- **Джерело даних** — зовнішній експорт (CSV/XML/JSON) з облікової системи

## Змінні середовища

| Змінна | Обов'язкова | Опис |
|---|---|---|
| `STORAGE_DATABASE_URL` | **так** | Рядок підключення до Neon (додає інтеграція Vercel). Перевіряються також `STORAGE_POSTGRES_URL`, `POSTGRES_URL`, `DATABASE_URL` та ін. |
| `IMPORT_TOKEN` | **так** | Спільний секрет для `/api/import-stock`. Згенерувати: `openssl rand -hex 32` |
| `SESSION_SECRET` | **так** | Ключ підпису cookie сесії. Згенерувати: `openssl rand -base64 32` |
| `ADMIN_PASSWORD` | **так** | Пароль до `/admin` |
| `ADMIN_USERNAME` | ні | Логін адміна (за замовчуванням `admin`) |
| `ADMIN_TOTP_SECRET` | ні | Base32-секрет двофакторної автентифікації адміна. Порожній — 2FA вимкнена |
| `SITE_URL` | ні* | Публічна адреса сайту (`https://домен`) для посилань у листах. *На Vercel підставиться адреса проєкту; на будь-якому іншому хостингу **обов'язковий** — інакше відновлення пароля вимкнеться, бо будувати посилання з заголовка `Host` небезпечно |

| `ORDER_EMAIL_FROM` | ні* | Відправник у Resend, **на верифікованому домені**. *Обов'язковий, якщо потрібне відновлення пароля поштою: з `onboarding@resend.dev` листи доходять лише вам. Перевірка: `npm run check:email` |

# 🚀 Як опублікувати сайт в інтернеті

Зараз сайт працює лише на `localhost`. Щоб він став доступним за реальною
адресою, потрібно виконати кроки нижче.

## Крок 0. Джерело товарів — база даних

Каталог береться з **Neon Postgres** (таблиця `products`). Порядок джерел
задано в [`lib/catalog.ts`](lib/catalog.ts):

1. **Postgres** — основне джерело (якщо задано `POSTGRES_URL` / `STORAGE_URL`)
2. Локальний файл `UKR_SKLAD_FILE_PATH` — резерв для офлайн-роботи
3. Порожній каталог — якщо нічого не налаштовано (сайт не падає)

### Таблиця `products`

Створюється автоматично при першому імпорті. Схема —
[`sql/001_products.sql`](sql/001_products.sql):

| Колонка | Тип | Опис |
|---|---|---|
| `sku` | `text` PRIMARY KEY | Артикул |
| `name` | `text` | Назва |
| `price` | `numeric` | Ціна |
| `stock` | `numeric` | Залишок |
| `updated_at` | `timestamptz` | Оновлюється автоматично |

### Завантаження товарів: `POST /api/import-stock`

```jsonc
// Запит
{
  "token": "<IMPORT_TOKEN>",
  "items": [
    { "sku": "00138", "name": "Свічка NGK CMR6H", "price": 130, "stock": 11 }
  ]
}

// Відповідь
{ "success": true, "updated": 1, "skipped": 0 }
```

- Невірний `token` → **403**
- Товар оновлюється за `sku`, новий — додається (upsert одним запитом на партію)

Готовий скрипт: [`scripts/import_stock.py`](scripts/import_stock.py)

```bash
set IMPORT_TOKEN=ваш-токен
set SITE_URL=https://ваш-сайт.vercel.app
python scripts/import_stock.py products.csv
```

## Крок 1. Обрати хостинг

Проєкту потрібен **Node.js-сервер**. Він використовує `proxy.ts`, API-роути та
Server Actions, тому **статичні хостинги не підійдуть**:

| Хостинг | Підходить? |
|---|---|
| **Vercel** | ✅ Найпростіше (творці Next.js), безкоштовний тариф |
| Railway / Render / Fly.io | ✅ Так |
| Власний VPS (Node + nginx) | ✅ Так |
| **GitHub Pages** | ❌ **Ні** — лише статика, не запускає сервер |

## Крок 2. Деплой на Vercel

1. Зареєструйтеся на https://vercel.com через GitHub
2. **Add New → Project** → оберіть репозиторій `Sasha-om/PanGospodar`
3. Vercel сам визначить Next.js. **Root Directory** залиште кореневим
   (репозиторій уже містить проєкт у корені)
4. Додайте змінні середовища (розділ **Environment Variables**):
   - `SESSION_SECRET` — **новий** ключ, згенерований `openssl rand -base64 32`
   - `ADMIN_PASSWORD` — **новий надійний** пароль
5. **Deploy**

Через ~2 хвилини отримаєте адресу `https://pangospodar.vercel.app`.

## Крок 3. Власний домен (необов'язково)

У Vercel: **Settings → Domains → Add**. Далі у реєстратора домену прописати
DNS-записи, які покаже Vercel. HTTPS-сертифікат видається автоматично.

## Крок 4. Перевірка після публікації

- [ ] Головна відкривається за HTTPS
- [ ] Каталог показує товари (якщо ні — див. **Крок 0**)
- [ ] `/admin` перекидає на `/login`
- [ ] Вхід в адмінку працює з новим паролем
- [ ] Кошик додає товари

## 🔒 Безпека перед публікацією

Репозиторій **публічний**, тому обов'язково:

1. **Згенеруйте новий `SESSION_SECRET`** — не використовуйте локальний
2. **Змініть `ADMIN_PASSWORD`** на надійний
3. Ніколи не комітьте `.env.local` (він уже в `.gitignore`)

> Cookie сесії має прапорець `secure` у продакшені — сайт **мусить**
> працювати за HTTPS, інакше вхід в адмінку не спрацює. Vercel дає HTTPS
> автоматично.

### Що вже вбудовано

- **CSP з nonce.** Політику формує `proxy.ts` (`lib/security-headers.ts`):
  виконуються лише скрипти з одноразовим nonce цього запиту, тож впроваджений
  `<script>` не запуститься. Решта заголовків (HSTS, X-Frame-Options,
  Permissions-Policy) — у `next.config.ts`.
  `style-src` свідомо лишає `'unsafe-inline'`: React рендерить `style={{…}}`
  як inline-атрибути, і для атрибутів nonce не існує.
- **Обмеження спроб входу** (`lib/login-rate-limit.ts`): 8 невдалих спроб /
  15 хв з однієї IP **і** 20 / год на один акаунт — друге правило зупиняє
  перебір з ботнету, де кожен запит має нову адресу.
- **Двофакторна автентифікація адміна** — опційна, вмикається змінною
  `ADMIN_TOTP_SECRET` (див. таблицю вище). Без неї нічого не змінюється.
  Задана змінна = код уже вимагається, тож **перед** тим, як покладатися на
  2FA, прожене `npm run check:totp`. Якщо код не приймається — приберіть
  змінну у Vercel і зробіть Redeploy, вхід одразу повернеться до пароля.
  Секрет із помилкою (у base32 немає `0`, `1`, `8`, `9`) не мовчить: форма
  входу прямо скаже, що змінну задано неправильно.
- **Відкликання сесій.** Зміна `SESSION_SECRET` миттєво розлогінює всіх (і
  адміна, і клієнтів) — це ж і спосіб «змінити пароль адміна»: `ADMIN_PASSWORD`
  живе у змінних середовища, тож ротація — це редагування змінної у Vercel і
  Redeploy.
  Для **одного клієнта** є точніший механізм: колонка `session_epoch` у
  `customers`. Cookie підписується тим номером покоління, який був чинним на
  момент входу; зміна пароля (і через лист, і в кабінеті) піднімає номер, тож
  усі інші сеанси цього акаунта миттєво перестають діяти, а браузер, у якому
  пароль змінювали, отримує свіжу cookie. Без цього зміна пароля не виганяла б
  того, хто вкрав cookie, — тобто не рятувала б саме в тому випадку, заради
  якого пароль і міняють.
- **Зміна пароля в кабінеті** (`/account/password`) — з підтвердженням
  поточного пароля. Сеансу самого по собі не досить: позичений ноутбук або
  вкрадена cookie не повинні дати можливість замкнути власника поза акаунтом.
- **Лист «пароль змінено».** Надсилається після кожної зміни — і через
  відновлення, і з кабінету. Саме він перетворює тихий захват акаунта на подію,
  про яку власник дізнається того ж дня.

- **Капча** (Cloudflare Turnstile). На **реєстрації** — завжди, бо там нема
  невдалих спроб, які можна порахувати: скрипт просто створює акаунти, і перший
  же коштує рядка в базі. На **вході** (адмін і кабінет) та у **відновленні
  пароля** — лише після 3 невдалих спроб. Ліміти вище зупиняють перебір одного
  акаунта, але не «один злитий пароль до тисячі акаунтів» — від цього рятує
  лише виклик, який людина проходить за дві секунди, а скрипт не проходить
  взагалі.
  Щоб увімкнути: dash.cloudflare.com → Turnstile → Add site (безкоштовно, без
  картки), і додати обидва ключі у Vercel. У налаштуваннях сайту в Cloudflare
  має бути ваш домен — інакше віджет не пройде перевірку, і **реєстрація
  перестане працювати** (там капча обов'язкова).
  Доки ключів немає — віджет не рендериться, скрипт Cloudflare не вантажиться,
  CSP лишається без сторонніх доменів.

### Чого ще немає (потребує вашого рішення)

- **Довіра до IP поза Vercel.** Ліміти рахуються за `x-vercel-forwarded-for`
  (його переписує сама платформа). Якщо сайт колись стане за Cloudflare,
  власним nginx чи піде на self-host — той фронт **мусить** перезаписувати
  `x-forwarded-for`, інакше IP можна підробити. Список заголовків — у
  `lib/client-ip.ts`.

**Важливо:** перевірка залишків зараз відбувається на клієнті. Коли з'явиться
реальне оформлення замовлень — обов'язково перевіряйте наявність товару ще раз
на сервері.

### Вітрина на головній

Головна має окрему полицю **«Офіційна техніка STIHL»** (компонент
`BrandShowcase`), а нижче — «Рекомендовані товари» з рештою брендів, щоб той
самий товар не показувався двічі. Обидва блоки беруть товари з **наявного**
каталогу (таблиця `products` / синхронізація з УкрСклад) — нічого окремо
заповнювати не треба. Полиця зникає сама, якщо у каталозі немає жодного товару
цього бренду: порожній брендовий блок гірший за його відсутність.

Бренд визначається колонкою `products.brand`, а якщо вона порожня — за назвою
товару (`detectBrand` у `lib/product-mapping.ts`), тож «Бензопила STIHL MS 250»
потрапляє на полицю навіть без заповненого бренду.

`check:email` відповідає на питання «чому не приходить лист відновлення».
`check:config` бачить лише, чи **задані** змінні; усе інше — на боці Resend і
звідси невидиме: домен доданий, але не верифікований; ключ від іншого акаунта;
відправник `onboarding@resend.dev`, з якого Resend доставляє **лише власнику
акаунта** (тобто вам — а клієнти не отримують нічого, і жодної помилки ніде не
видно). Скрипт питає про це сам Resend:

```bash
npm run check:email                     # конфігурація + список доменів і їх статус
npm run check:email -- you@example.com  # ще й справжній тестовий лист
```

`check:config` і `check:totp` читають `.env.local`. Щоб перевірити **бойові**
значення, спершу підтягніть їх із Vercel:

```bash
npx vercel env pull .env.local
```

`check:config` не друкує значень — лише те, чи задані вони й чи має сенс їхня
форма. Він ловить саме тихі помилки: `TURNSTILE_SITE_KEY` без префікса
`NEXT_PUBLIC_` (значення не потрапляє у браузер, віджет просто не з'являється),
`SITE_URL` без `https://`, `ORDER_EMAIL_FROM` не у форматі адреси,
`ADMIN_TOTP_SECRET` не в base32.

> **Увага:** змінні з префіксом `NEXT_PUBLIC_` вбудовуються у збірку, а не
> читаються під час роботи. Після їх зміни потрібен саме **Redeploy**.

### Оновлення залежностей

`npm update` безпечний. Два мажори свідомо не піднімаємо — вони ламають саме
перевірку коду, а не наш код:

- **TypeScript 7** — `typescript-eslint` (усередині `eslint-config-next`) його
  ще не підтримує, `npm run lint` падає з «does not support TS 7.0».
- **ESLint 10** — `eslint-plugin-react` у складі `eslint-config-next` викликає
  API, якого в ESLint 10 уже немає.

Обидва варто спробувати ще раз після наступного мажора `eslint-config-next`.
